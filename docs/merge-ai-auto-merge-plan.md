# AI 自动合并计划

状态：规划中。目标：为三栏合并工具提供“建议合并”，不绕过用户确认，不直接覆盖工作区。

## 边界

- 现有 Git 三方合并仍是唯一事实来源。
- AI 只处理尚未解决的冲突块；非冲突内容继续由本地算法自动合并。
- 默认不发送仓库内容。首次启用必须明确说明数据范围、模型与隐私选项。
- 每条建议可查看输入片段、理由、置信度与预计结果；用户点击“应用建议”后才写入中间结果。
- 任何建议可用 Ctrl+Z 撤销，并保留当前合并会话的取消确认。

## 阶段

1. **候选收集**
   - 读取冲突块前后有限上下文、文件类型、base/local/remote 三份文本。
   - 过滤二进制、超大文件、密钥和明显敏感路径。
   - 先运行确定性规则：相同行、单边删除、无重叠插入、格式化差异。

2. **AI 建议任务**
   - 异步任务，显示独立进度与取消按钮，不阻塞编辑器滚动或手动处理。
   - 每个冲突块单独请求，避免一个失败导致整个文件不可用。
   - 要求模型输出结构化补丁：结果行、解释、置信度、是否需要人工复核。

3. **预览与应用**
   - 在中间结果栏以建议色预览，不立即修改 `MergeDocument`。
   - 支持逐块应用、全部高置信度应用、忽略建议、手动编辑。
   - 应用后走现有 undo/redo 栈，并重新计算未解决冲突数量。

4. **校验与写入**
   - 校验输出无冲突标记、文本编码正常、文件大小合理。
   - 对代码文件可选运行轻量语法检查；失败时降级为“需人工确认”。
   - 最终仍由用户点击“应用”写回工作区并按当前流程暂存。

5. **测试**
   - 覆盖空白差异、删除/修改、独立插入、重复行、超长文件、取消、断网和模型异常。
   - 覆盖隐私拒绝、上下文裁剪、建议应用后 Ctrl+Z/Redo、关闭合并窗口未保存提示。

## 明日第一步
